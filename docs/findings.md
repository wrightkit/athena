# Findings

Behavior currently believed about the Workshop client, each tied to the probe that supports it. This is a reading aid, not an authority: the evidence, run count and result are in `probes/<id>/capture.json`, and a statement here is only as firm as that record. A statement leaves this list if its capture is re-judged `mismatch` or goes stale.

Check `runs` and `result` in the capture before relying on one.

## Scheduling

- The tick is 16 ms (P0, P1).
- Wait rounds up to a whole number of ticks (P1).
- `Wait Until(True, 0)` takes 0 ticks; `Wait(0)` takes 1 tick (P4).
- Ongoing is edge-triggered; an edge that occurs while the rule is in a Wait is dropped, not queued (P2).
- Rules whose conditions become true on the same tick run in file order when the rule that sets the condition is earlier in the file (P3).
- When the rule that sets the condition is later in the file, the earlier rules see the change one tick later (P3 driver-last).
- Wait Behavior (P6), with a condition that goes true, false, true, false while the rule waits 1 s: `Ignore Condition` finishes the wait and drops the later edges; `Abort When False` abandons the rest of the actions when the condition goes false, and a later true edge starts a new run; `Restart When True` restarts the full wait at the new true edge.

## Values

- `Position Of` read inside an action changed on every tick; the 12.5 Hz refresh hypothesis was not supported (P5). `Update Every Frame` made no difference in that access pattern and was not tested inside continuously re-evaluated elements.

## Inspector

- Log lines are prefixed `[mm:ss]`, so they cannot time anything.
- `Custom String` shows numbers with two decimals; the variable block shows three. Probes print milliseconds for that reason.
- Within one capture, whole-number values print either bare (`0`, `1056`, `1424`) or with two decimals (`1008.00`), so a formatter cannot assume one form.
- The native variable export omits variables whose value is zero (P6 `endAbort`).

The client version is recorded per capture in `capture.json` under `client.version`.

## Modeled, not measured

Simulator choices no capture backs yet — the detail lives in [architecture.md](architecture.md#choices-no-capture-covers-yet):

- `Ongoing - Each Player` per-player instantiation (instance order, per-instance edge and wait state) and the `team`/`player` filters of rule events, including hero-name targets (athena#46).
- `For Global Variable`/`For Player Variable` execution: bound evaluation points, the exit-check direction by step sign, and the `End` jump back to the first body action (athena#50).
- `Workshop Setting *` values (`Real`, `Integer`, `Toggle`, `Combo`, `Hero`) evaluate to their declared `default` argument — one lobby, no player-edited settings; a `Hero` default yields its member id as text (athena#54).
- Control-flow actions (athena#58): `Skip`/`Skip If` (a positional jump — it can land inside a block the jump never entered; a `True`/`False` count coerces to 1/0 and a negative count skips nothing), `Abort`/`Abort If` (ends the whole run, subroutine frames included; the timeline records it `aborted`), `Loop`/`Loop If`/`Loop If Condition Is True`/`Loop If Condition Is False` (restart the current frame's action list — inside `Call Subroutine`, the subroutine's own — with the condition list re-checked per pass), and `Break`/`Continue` inside `While`/`For` (`Continue` lands on the `End`, which steps a `For` or re-enters a `While` head; `Break` lands past it; outside a loop they are `not_modeled`).
- General and array values plus `At Index` variable writes (athena#56): truthiness and `Null`/boolean number coercions, `==`/`!=` element-wise array equality, `Round To Integer` modes, `Null` read as the empty array, past-end append and out-of-range no-op index writes, `Remove From Array By Value` dropping every match.
- Element-context array values and `Evaluate Once` (athena#60): `Filtered Array`/`Sorted Array`/`Is True For All`/`Is True For Any` bind `Current Array Element` and `Current Array Index` per element and read `Null` as the empty array, `Sorted Array` orders ascending by a numeric key with equal keys keeping place, `Is True For All`/`Any` stop at the deciding element and read the empty array as true/false, `Current Array Element`/`Index` outside an element context are `not_modeled`, and `Evaluate Once` pins its operand's first read per site for the rest of one scope — a rule-instance run (loop bodies and restarted frames re-read the site into the pin; a `Wait` keeps the pins, and the next run start or restart clears them), one rule-condition check pass, or one `Wait Until` call's per-tick re-checks — and is `not_modeled` inside an element-context operand. `Mapped Array` stays `not_modeled`.
- Statuses, buttons, effects and `Start Rule` (rest of athena#58): `Set Status`/`Clear Status`/`Has Status` expiries on `Total Time Elapsed`, `Allow`/`Disallow Button` writes, `Is Button Held` as a live scenario input (`buttons`), `Start Rule` timing and `ifAlreadyExecuting` behavior, `Create`/`Play`/`Destroy Effect` entities recorded like HUD without geometry, `Last Created Entity`, and the `Stop Chasing` no-op.
- Random values (athena#65): the client's generator and distribution are unmeasured, so the scenario supplies the source — `random.seed` drives a splitmix64 stream the `Random *` values consume in evaluation order, one fraction `u ∈ [0, 1)` per draw. `Random Integer` floors its bounds and is inclusive (a `Min` past `Max` swaps them), `Random Real` is `min + (max−min)·u` on `[min, max)`, `Random Value In Array` on an empty array yields `Null` without a draw, and `Randomized Array` is a Fisher-Yates shuffle of the same stream. A random value without a `random` source is a `missing_input`, and each draw is recorded as a `randomDraw` change.
- String values (athena#57): string parameters read an `Empty Array` argument as the empty string and coerce other scalars by the `Custom String` render coercion; `Char In String` yields `""` outside the string's bounds, `String Split` splits an empty separator into characters and an empty source into the empty array, `Index Of String Char` reports a character index or -1 (always -1 for an empty needle), `String Replace` replaces every occurrence (an empty pattern is `not_modeled`), and a `Custom String` placeholder without an argument stays literal. A produced string over 511 bytes is `not_modeled` — whether the client's byte cap was removed or covers every produced string is unmeasured, the sources conflict. The display-only strings (`Icon String`, `Hero Icon String`, `Ability Icon String`, `Input Binding String`) became opaque display values under athena#113.
- Server load values (athena#67): `Server Load`, `Server Load Average` and `Server Load Peak` are a client-measured quantity the simulator must not guess, so the scenario supplies them as the `serverLoad` constant the run reads; real load varies per tick. A read without `serverLoad` is a `missing_input`.
- `All Heroes` (athena#69): yields the `Hero` member ids in catalog order; the client's element order is unmeasured, so the catalog order is the modeled order.
- The map (athena#71): `Current Map` reads the scenario's `map` — the lobby chooses the map outside the script, so the map is a scenario constant and mid-run changes are not modeled. The value yields the catalog `Map` member id as text, the form a `Map` literal yields, so the two compare equal. A read without `map` is a `missing_input`.
- Vector values and player position/facing (athena#74): the catalog's deterministic vector math (`Vector`, the components, `Vector`/`Direction Towards`, `Distance Between`, `Direction From Angles` and its inverse pair, `Dot`/`Cross Product`, `Normalize`, `Magnitude`, `Angle Between Vectors`, vector `Add`/`Subtract`/`Multiply`/`Divide` with a `Player` read as its `position`) in the x-left/y-up/z-forward frame, horizontal angle 0 forward increasing left and vertical 0 level increasing downward, and the per-player `position`/`facing` constants a scenario supplies — `Position Of`, `Facing Direction Of`, `Local`/`World Vector Of` (`ROTATION`, `ROTATION_AND_TRANSLATION`) read them, an omitted field is a `missing_input` naming it. Zero-length vectors (`Normalize`, `Direction Towards`, `Angle Between Vectors`), a non-finite produced component (division by zero among the causes), a `Custom String` render of a vector and `Eye Position`'s hero eye height stay `not_modeled`.
- The empty world (athena#75 decision, athena#77): **empty world, modeled not measured**. The run has no map geometry, so a raycast never hits and answers by the catalog's no-hit return — `Ray Cast Hit Position` the end position, `Ray Cast Hit Player` `Null`, `Ray Cast Hit Normal` the direction from the end back to the start (a zero-length cast is `not_modeled`) — `Is In Line of Sight` is true, `Nearest Walkable Position` yields its input, `Is On Ground` is true and `Is In Air`/`Is On Wall`/`Is In Spawn Room` are false. `Teleport` writes the scenario `position` and records a `world` change of field `position`; `Apply Impulse` needs a velocity the model does not carry and stays `not_modeled`, as do the motion queries `Is Moving`/`Is Standing` and `Eye Position`'s unrecorded eye height. The trace marks the model as `geometry: "emptyWorld"` so the viewer can warn that geometry-dependent results are not real.
- Objective positions (athena#82): the map and mode place the objectives outside the script, so `Objective Position(i)` reads `objectives[i]` of the scenario — a constant list of positions, the index being the evaluated argument under the number coercion (`False`/`True` as 0/1, the catalog's index "starting at 0 and counting up"). A read with no `objectives` field or an index naming no entry is a `missing_input` naming `objectives[i]`; other objective-derived values (`Objective Index`, `Is Objective Complete`, …) stay `not_modeled`, and objective movement is not modeled.
- `Is Hero Being Played` (athena#84): true when at least one scenario player on the team — `All Teams` selects every player — has the hero as its declared `hero`; what the hero-selection screen shows is not modeled. The arguments resolve to catalog member ids, the form `Hero Of`/`Team Of` yield; a player on the team without a `hero` is a `missing_input`, and an argument that is not a catalog member after evaluation is `not_modeled`.
- `Players On Hero` (athena#86): the scenario players on the team — `All Teams` selects every player — that have the hero as their declared `hero`, in roster order; what the hero-selection screen shows is not modeled. The arguments resolve to catalog member ids, the form `Hero Of`/`Team Of` yield; a player on the team without a `hero` is a `missing_input`, and an argument that is not a catalog member after evaluation is `not_modeled`.
- The lobby slot (athena#99): `Slot Of(player)` reads the scenario player's `slot` — the lobby seats players outside the script and roster order is not a measured slot, so the field is a scenario constant, never derived or defaulted. A read on a player without `slot` is a `missing_input` naming `slot`, and a `Slot N` rule-event filter matches the same field — a player without one does not match.
- `Value In Array` on a non-array operand (athena#97): a non-array operand (`Null`, number, text, vector, player, boolean) has no element at any index, so it yields the catalog's "element does not exist" answer — the same `Null` an out-of-range index yields. Basis: the catalog's `valueInArray` sentence ("The value found at a specific element of an array. Results in 0 if the element does not exist.") and `firstOf` sentence ("The value at the start of the specified array. Results in 0 if the specified array is empty."); the catalog does not state the non-array case explicitly. `First Of` of `Null` and of the empty array already answer the same way (`Null`). A probe is needed before this counts as measured.
- Actions with no readable effect (athena#103): actions the catalog ties to no readable value run as no-ops — arguments still evaluate left to right, the run records in `timeline` as usual, and no `changes` are produced. The no-op set: `disableInspector` ("stop recording new entries"), `disableBuiltinGameModeAnnouncer` ("game mode announcements"), `disable`/`enableBuiltinGameModeMusic` ("game mode music"), `disableBuiltinGameModeCompletion`, `disableBuiltinGameModeScoring` and `disable`/`enableRespawn` (flags gating game-mode completion, scoring and auto-respawn the simulator does not run), `disableGameModeHud`, `disableGameModeInworldUI`, `disableHeroHud` (HUD visibility; no value reads it), `disable`/`enableMovementCollisionWithEnvironment`, `disableMovementCollisionWithPlayers` (collision flags gating physics the model does not run), `start`/`stopCamera`, `startForcingName`, `start`/`stopForcingOutlineFor`, `start`/`stopModifyingVoicelinePitch`, `start`/`stopScalingBarriers`, `start`/`stopScalingSize`, `preloadHero`. `Destroy All Effects` is modeled for real — it removes every live `effect`/`beam` entity. The remaining create action the catalog binds to a readable id, `createDummyBot` (a mutable roster the model does not carry), stays `not_modeled`, as does everything that moves, damages, scores or changes state a value exposes.
- The match phase (athena#101): the catalog's six phase reads — `Is Waiting For Players`, `Is Assembling Heroes`, `Is In Setup`, `Is Game In Progress`, `Is Between Rounds` and `Is Match Complete` — each describe exactly one phase, and the simulator runs no match, so the scenario's `matchPhase` supplies the phase as a constant and each read answers true exactly for its own phase. Overtime is no phase the catalog defines, so `matchPhase` cannot express it. A read without `matchPhase` is a `missing_input` naming `matchPhase`.
- The game mode, the local player and the remaining Bastion reads (athena#105): `Current Game Mode` reads the scenario's `gameMode` — the lobby chooses the mode outside the script, so the mode is a scenario constant — yielding the catalog `Gamemode` member id as text, the form a `Game Mode` literal yields, so the two compare equal; a read without `gameMode` is a `missing_input` naming `gameMode`, and a mid-run change is not modeled. `Local Player` reads the one scenario player marked `local`; a read with no marked player is a `missing_input` naming `local`. Three more live inputs read the version-2 `state` map — `Is Using Ability 1`, `Is Using Ability 2` and `Is Firing Primary` (`isFiringPrimaryFire`). The catalog's derivations gain `Last Of` (the array tail; `Null` on an empty array, the same `0` the catalog's `firstOf`/`lastOf` sentences promise), `Sine From Radians` (a non-finite argument is `not_modeled`), `Vertical Facing Angle Of` (the vertical component of the scenario `facing`) and `Players Within Radius` (the scenario players on the team within the distance, in roster order — the catalog notes dead players are picked up, so no life-state filter applies — with `losCheck` evaluated but holding in the empty world). `Remove From Array` joins them: "one or more values removed (if found)" settles all-match removal, the removal `Remove From Array By Value` already performs on a copy, and an array operand drops every element matching any element it holds — "each matching element is removed". Reads the catalog leaves to state the model does not carry stay `not_modeled`: the roster and life counts (`All Living Players`, `Number Of Players`, `Players In Slot`), the match clock (`Match Time`, `Is Match In Overtime`), spawn points, player statistics, the health-pool/heal-over-time ids, `Throttle Of`, `Is Jumping`, `Mapped Array`'s closure, the event-scoped values, and the host player without a `host` mark.
- `Is Duplicating` (athena#111): the duplication flag is a per-player fact no Bastion action can change, so it joins the version-2 `state` map as the `isDuplicatingAHero` key — scenario-supplied, not simulated; the catalog's "Whether the specified player is duplicating another hero" names no other state the model carries.
- `Null` in a vector position (athena#108): an unset variable reads `Null`, and a `Null` where a `Vector` operand is expected is the zero vector — the same default-zero read `number()` makes of `Null` in a number position (`Null` and `False` are `0`). Basis: the model's other default-zero reads (`==`, arithmetic operands, array positions reading `Null` as the empty array), the catalog's `zeroAsNull`/`nullVectorAsNull` literal-substitution facts that make `0`, `Null` and `Vector(0, 0, 0)` interchangeable, and `Teleport`'s `Vector` position already reading an evaluated `Null` as the origin. The rule covers every strict `Vector` position the model answers — the component accessors, the products, `Normalize`/`Magnitude`, the angle-from-direction values, the `Local`/`World Vector Of` vector argument, the position reads (`Distance Between`, `Vector`/`Direction Towards`, `Players Within Radius`' center, `Nearest Walkable Position`, the raycast start/end) — so the zero-length guards still stop: `Normalize`/`Direction Towards`/`Angle Between Vectors` on `Null` meet their zero-length vector and stay `not_modeled`. A literal number, boolean, text or array is not a vector and stays `not_modeled`. `Horizontal Angle Towards`/`Vertical Angle Towards` are not modeled at all, so the question does not reach them. A probe is needed before this counts as measured.
- Opaque display values (athena#113): the five display-only producers — `Icon String`, `Hero Icon String`, `Ability Icon String`, `Input Binding String` and `Custom Color` — yield a client rendering token no modeled construct reads, so the value carries the producer id and the evaluated arguments (`{ "type": "display", "value": { "producer", "args" } }`), never the glyph, key name or RGB. It flows through variables, arrays and the text/color arguments of HUD and effect actions; a `Custom String` holding one yields a `customString` display value (template as first argument) because the rendered text would carry the token's content. `==`/`!=` between two display values answer from the structure — identical producer and recursively-equal arguments; a `customString` display, whose content is the rendered text rather than its record, stops every comparison it touches, as does any comparison against a different structure or a literal, and any content read — the string reads, arithmetic, an array index, a sort key, the number/truthy/string coercions. HUD and effect `color` arguments now record the evaluated value: a `Color` member still serializes as the bare member id, a `Custom Color` as the display `Val`. No capture covers the client tokens; modeled, not measured.
- State cells and stored modifiers (athena#116): the version-2 `state` map gains a write side — a state-write action writes a cell over the declared map, a write defines a key the scenario never supplied, a read after a write returns the written value, and a read before any write of an undeclared key stays `missing_input`; every write records a `state` change (`player`, `key`, `old`, `new`). The writes, each by its catalog sentence: `setUltCharge` writes `ultCharge` ("sets the ultimate charge for one or more players as a percentage of maximum charge"), the `Number|Boolean` parameter reading `False`/`True` as `0`/`1`; `setHealth` ("sets the health of a player or players … This action only has an effect on living players. For dead players, use the Resurrect action instead") writes `health`, gated by the `isDead` read — a dead target is skipped, an unanswerable `isDead` is a `missing_input`; `setMaxHealth` ("as a percentage of their max health … will ensure that a player's current health will not exceed the new max health") writes `maxHealth` off the current-max read and clamps `health`; `kill`, `respawn` and `resurrect` write `isDead` — `respawn` also `health` to the `maxHealth` read ("with full health"), its spawn relocation not simulated — and `setFacing` `To World` writes the scenario `facing` to the direction's angles (`To Player` stays `not_modeled`: the catalog does not state the composition). The stored modifiers record a `modifier` change (action, player, evaluated non-target arguments) and land on the player's `modifiers` — nothing reads them back and no readable value moves: `setUltEnabled` → `ultEnabled`, `setAbility1Enabled`/`setAbility2Enabled` → `ability1Enabled`/`ability2Enabled`, `setDamageDealt`/`setDamageReceived`/`setHealingDealt`/`setHealingReceived` → `damageDealt`/`damageReceived`/`healingDealt`/`healingReceived` (scales on damage the model does not run), `setMoveSpeed`/`setGravity`/`setKnockbackReceived` → `moveSpeed`/`gravity`/`knockbackReceived` (movement modifiers no modeled read consumes — `isMoving`/`getSpeed` are scenario state, never derived from them), `setAllowedHeroes` → `allowedHeroes` (no hero read consults the list), `startForcingHero`/`stopForcingCurrentHero` → `forcedHero` written/removed, and `startForcingSpawn` → `forcedSpawnRoom` on each player of the team. The rest of PR #104's list — and the sibling ids in the same families (`stopDamageOverTime`, `stopAllDamageOverTime`, `stopAllHealingOverTime`, `stopFacing`, the player-variable `Chase *`) — stays `not_modeled`, each needing a model the run does not carry: the health-pool ids and composition (`addHealthPool`, `removeHealthPool`), the damage/heal-over-time and damage-modification ids (`startDamageOverTime`, `stopDamageOverTime`, `stopAllDamageOverTime`, `startHealingOverTime`, `stopHealingOverTime`, `stopAllHealingOverTime`, `startDamageModification`), the roster (`createDummyBot`, `destroyAllDummies`, `removeFromGame`), the entity ids (`createIcon`, `destroyAllIcons`) and text ids (`createInWorldText`, `createProgressBarInWorldText`, `destroyInWorldText`, `destroyProgressBarInWorldText`, `destroyAllInWorldText`), button and throttle forcing (`forceButtonPress`, `startForcingButton`, `stopForcingButton`, `startForcingThrottle`, `stopForcingThrottle`, `startThrottleInDirection`, `stopThrottleInDirection`), `cancelPrimaryAction` (the stun's duration is unstated), the dynamics of position, velocity and facing (`applyImpulse`, `startAcceleration`, `stopAcceleration`, `startFacing`, `stopFacing`, `startForcingPosition`, `stopForcingPosition`, `attachTo`, `detach`), the match clock and match state (`pauseMatchTime`, `unpauseMatchTime`, `setMatchTime`, `setSlowMotion`, `declareTeamVictory`, `restartMatch`), and the `Chase *` schedules (`chasePlayerVariableAtRate`, `chasePlayerVariableOverTime`, `chaseGlobalVariableAtRate`, `chaseGlobalVariableOverTime`). No capture covers any of these; modeled, not measured.
